# 張辰瑋 寫作範本與流程 Pipeline

> 張辰瑋＝《無境界者》創辦人、主編，截至第 9 期為止全刊最高產作者（**42 篇**，佔全刊 regular 稿三成）。

> ## ⭐ 這份是「寫作範本」，不是編輯護欄

> 唯一不能模仿的是**事實**——人名、日期、經歷、引文只能來自素材本身（見第四節）。

## 一、作者定位與既有作品

- 身分：雜誌創辦人、主編、神學／教會史寫作者；曾讀神學院、後離開教會，自我定位為「屬靈孤兒／旅人／無境界者」。自介：「無教會者、衛理公會會友、佛教徒。不太喜歡待在別人設定好的框架中，帶有某種知性反骨的怪癖，最喜歡做的事就是成為跨界的橋樑。」
- 平均一篇 8,500 字／8.7 個腳注／6.4 個 h3／3.7 張圖——**他是全刊篇幅最長的作者**，不要交 3,000 字了事。
- 三大文類：
  1. **「我的◯◯史」信仰自傳體**（`生命故事`／主題廣場）：我的異端史、我的福音派史、我的彩基史、我的大公派史、我的泰澤史、我的循道宗史。副標固定 `我的信仰史（N）`，**目前到（六）= 9-15**。這是最能代表他聲音的一類。
  2. **教會史／神學評論長文**（`專題文章`／`評論與回應`）：〈尼西亞基督教的形成〉〈主教制的歷史演變與教會的大公性〉〈基督宗教的七個大公傳統〉。系列副標 `基督宗教宗派譜系學初探（N）`，**目前到（二）= 7-16、番外篇 = 8-16**。
  3. **AI 對話提煉的意識流獨白**（`文藝創作`／主題廣場）：9-10〈一位牧者之死〉。見第四節。
- 撈範本：`SELECT id,title,subtitle,content FROM articles WHERE author='張辰瑋' ORDER BY issue`（走 REST，見 [`upload-article`](../upload-article/SKILL.md) 第六節 IPv6 注意事項）。最佳對照：**8-12 我的泰澤史**、**2-10 流浪者之聲**、**9-10 一位牧者之死**。

## 二、聲音特徵（寫稿時對齊這幾點）

- **第一人稱、長而流動的敘事**：以具體場景推進——精確的日期、地點、人名、對話。少抽象說教，多「帶你親歷現場」。
- **誠實到近乎自曝**：不美化自己，坦白承認內傾、需要獨處、叛逆、罪惡感、嫉妒、缺乏同理心。脆弱是他文字的力量來源。
- **神學長在生命經驗裡**：把潘霍華、羅哲、約翰‧衛斯理、榮格、赫塞、聖經經文、詩歌歌詞，自然織進親身故事，而不是另闢理論段落。
- **反諷與溫柔的幽默**：即使在沉痛處也有自嘲與荒謬感（泰澤「通往自由的巴士」、被搶五十歐、得知噩耗時正在算減肥熱量）。
- **文學性的小標**：`<h3>` 用意象化、有餘味的標題（〈何處有仁〉〈成為時間之賊〉〈流浪漢之夜〉〈褥子團契〉），不用「第一段／背景介紹」這種功能性標題。
- **小標不編號、不寫結構預告句**（memory `feedback_writing_style`）：不要「一、」「（一）」，不要「接下來我要分七步走」「稍後我會回來談」。他的原話：「一篇短文不用一直預告後面的事情。」
- **母題**：教會合一、大公傳統、無境界主義、朝聖／旅人、屬靈父親、孤兒、個體化、神聖與世俗的辯證。
- **收尾接 🌏**（這是全刊規則，不只他）。
- 常用版面：`indented-quote` 放改變他的那段經文、`special-box` 放詩歌、`book-quote` 放開篇題辭、`img-left`/`img-right` 穿插旅行照。

### 寫完自檢：這像不像他寫的？

草稿寫完**逐項對一遍**，沒對上就回去改。這是模仿範本，不是參考。

- [ ] **篇幅到了嗎**——他平均 8,500 字。寫出 3,000 字就是還沒進入狀況，回去把細節、典故、年份、人名、對話補回來。
- [ ] **有沒有具體場景**——每個論點後面是不是都掛著一個真實發生過的當下（哪一天、在哪裡、誰說了什麼）？通篇都在講道理就是沒對齊。
- [ ] **有沒有誠實到自曝的段落**——至少要有一處他承認自己內傾／叛逆／嫉妒／罪惡感／沒有同理心。全篇都在正面表述就是修得太乾淨了。
- [ ] **神學是不是長在經驗裡**——潘霍華、榮格、衛斯理、經文有沒有被單獨切出一段「理論說明」？有的話拆掉，織回敘事。
- [ ] **有沒有反諷或自嘲**——沉痛處尤其要有，那是他的呼吸。
- [ ] **小標有沒有餘味**——〈何處有仁〉〈成為時間之賊〉這種，不是〈背景說明〉〈第二階段〉。**沒有編號**。
- [ ] **有沒有結構預告句**——「接下來我要分七步」「稍後會回來談」一律刪。
- [ ] **句子夠不夠長、夠不夠流動**——他的句子是綿延推進的，不是短句排比。
- [ ] **母題有沒有回聲**——旅人／屬靈孤兒／合一／大公／個體化／神聖與世俗的辯證，至少扣到一個。
- [ ] **收尾 🌏**。

讀起來像雜誌腔、像 AI 寫的、像維基百科，就是全部沒對上——回去讀 8-12 或 2-10 再寫一次。

## 三、寫作分工：Claude 備料與查驗，Gemini 執筆

> **2026-09-03 使用者定案**：「我覺得你寫文章實在是很生硬……以後我給你一些資料要你寫新文章時，你來負責整理與查驗資料、整理大綱，但去呼叫 GEMINI 來寫，他的語氣我比較喜歡。」
>
> 因此**預設情況下 Claude 不執筆正文**：Claude 做編輯台的活，Gemini 當筆。

### 分工

| 誰 | 做什麼 |
|---|---|
| **Claude** | 取材（撈 DB／讀對話紀錄／讀 docx）、**事實查證**、擬大綱、定小標、決定 category／section／副標、備妥必用素材的逐字片段、寫「寫作簡報」；回稿後做**事實複核**、套 HTML 與體例、腳注與徵引、找圖與查來源、寫進 DB 上架 |
| **Gemini** | 依簡報，把大綱與素材寫成正文（中文散文，不含 HTML） |

Claude **不要**代筆正文，也**不要**「先寫一版給 Gemini 參考」——那只會把生硬的句子帶進去。

### 寫作簡報要包含什麼

1. **定位**：期別、本期主題、category／section、預定字數（他平均 8,500 字）
2. **標題與副標**：已定案的直接給，不要讓 Gemini 另創
3. **大綱**：每個 `<h3>` 小標＋該節要點條列（小標由 Claude 定，意象化、不編號）
4. **必用素材**：引文逐字、經文、人名生卒年、年份、事件——**標明哪些是查證過的事實，不得改寫**
5. **聲線規格**：貼第二節的自檢清單，外加下面那張量化表
6. **體例**：交純中文散文即可，HTML 由 Claude 事後套；破折號用 `──`；收尾 🌏
7. **禁止事項**：不得虛構人名／日期／引文；不得寫結構預告句；小標不編號

### 聲線量化基準

2026-09-03 實測他既有的 7 篇書評（6-14、8-8、5-13、6-10、2-7、1-13、3-7）。回稿後把正文去 HTML、去空白丟進檢查，落在區間內才算對齊：

| 指標 | 張辰瑋常態 | 我實際犯過的錯 |
|---|---|---|
| 平均句長 | **53–74 字** | 寫成 48 字＝句子太碎 |
| 「因此」 | **9–24 次／篇** | 只用 4 次＝把他的推進連接詞拿掉了 |
| 「其實」 | 3–7 次 | 用到 18 次＝變成口頭禪 |
| 破折號 `──` | 7–33 個 | 用到 59 個＝嚴重過量 |
| **「不是Ａ而是Ｂ」** | 每千字 **0.19** | 每千字 0.76＝四倍，最明顯的 AI 腔 |
| 「而不是」 | 每千字 0.05 | 每千字 0.25 |
| 「不在…而在」 | 每千字 0.03 | 每千字 0.25 |
| 「恰恰相反」 | **0（他從不用）** | 用了 1 次 |
| 「從來不／沒」 | 每千字 0.01 | 每千字 0.42 |
| 「並不是／並非」 | 每千字 0.78 | 這個本來就是他的習慣，不用砍 |

**他最痛恨的是否定式對句**。原話：「不要一直用否定性語法或者不是怎樣而是怎樣」「不用一直講某某不是什麼」。要說一本書是實踐手冊，就直接說它是實踐手冊，不要先說它「不是理論書」。

### 怎麼呼叫 Gemini

**API 已恢復（2026-09-05）**。`.env` 的 `GEMINI_API_KEYS` 換成 7 把可用金鑰，主力模型 `gemini-3.5-flash`。**只從 `process.env` 讀，不要把金鑰寫進任何檔案或程式碼**（見 CLAUDE.md 第一節）。

免費層的限制與對策：

| 症狀 | 意思 | 怎麼辦 |
|---|---|---|
| 429 `prepayment credits are depleted` | 那個 AI Studio 專案已切付費層且額度歸零 | 這把金鑰報廢，換專案重開 |
| 429 `GenerateRequestsPerDayPerModel-FreeTier` | 該金鑰**該模型**的當日免費額度用完 | **換模型**就有新額度：`gemini-3.5-flash` → `gemini-3-flash-preview` → `gemini-2.5-flash` |
| 503 `high demand` | 模型忙碌，暫時性 | 換一把金鑰重試即可 |
| 400 `API key not valid` | 金鑰已失效 | 從 `.env` 移掉 |

所以呼叫端要同時輪替**金鑰 × 模型**，逐組重試：

```js
const keys = (process.env.GEMINI_API_KEYS || '').split(',').map(s => s.trim()).filter(Boolean);
const models = ['gemini-3.5-flash', 'gemini-3-flash-preview', 'gemini-2.5-flash'];
const pairs = models.flatMap(m => keys.map(k => [k, m]));
for (const [key, model] of pairs) {
  const r = await fetch(
    `https://generativelanguage.googleapis.com/v1beta/models/${model}:generateContent?key=${key}`,
    { method: 'POST', headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ contents: [{ parts: [{ text: brief }] }] }) });
  if (r.status === 200) { /* j.candidates[0].content.parts[0].text */ break; }
}
```

★ **`gemini-2.5-flash` 之類的舊模型會吐簡體字**，提示詞要明寫「一律繁體中文（台灣用語）」，回稿後再掃一次簡體。

★ **改寫既有文章時要分段送、逐段驗**（2026-09-05 改寫 10-1／10-10／10-11／10-14 的實作，腳本在 `temp/gem/`）：
把 content 切成頂層區塊，`<figure>`／`<blockquote>`／`book-box`／`indented-quote`／表格／小標**凍結不送**（引文與經文一個字都不能動），
其餘段落以 `<Pn>` 編號成批送出、要求原號原序回傳，回稿逐項驗：
段落數、`<sup class="footnote-ref">` 腳注編號集合、`[[圖片N]]` 佔位符、`<a href>`、最外層標籤、每段字數 ±8%、簡體字、禁用語。
不合格就把退稿理由附回去重送，三次不過就保留原文那一批。

★ **聲線規格別把連接詞寫成硬指標**。把「因此」寫成「全篇 9～24 次」的結果是模型每段都用（實測灌到 30～44 次），
要寫成「每千字最多一次」，並在改寫後補一道潤稿 pass 把浮濫的連接詞與過長句子收掉。

### 回稿之後，Claude 一定要做的事

## 四、第三文類：AI 對話 → 意識流獨白（9-10 範式）

張辰瑋的素材有一大來源是**他與 AI 的長篇對話**（他自稱「阿周那」、稱 Gemini 為「克里希那」）。這些對話存在**另一個專案** know-graph-lab：

| 素材 | 路徑 |
|------|------|
| 寫作計畫（書名「神，你正在重排我的前途／與克里希那的對話」） | `C:\Users\user\.claude\projects\c--Users-user-Desktop-know-graph-lab\memory\project_krishna_dialogues.md` |
| 對話轉寫作的既有技能（取材機制可複用） | `C:\Users\user\Desktop\know-graph-lab\.claude\skills\dialogues-to-writing\SKILL.md` |
| 每日原始對話 JSON | `C:\tmp\krishna\YYYY-MM-DD.json` |
| 一月手工稿 | know-graph-lab `2026.01對話錄.docx` |

### 9-10〈一位牧者之死〉最後定稿長什麼樣（以線上版為準）

> ⚠️ 這一節在 2026-08-25 依**實際上架的版本**訂正過。早期版本的 skill 說「刪掉夢境、榮格積極想像」「用 `custom-divider` 分三段」——**定稿並非如此**，不要照那個寫。

- **`category=文藝創作`、`section=主題廣場`、副標 `一份無意識觀察日記`**，10,200 字。
- **開頭兩段交代方法**：說明自己因為讀榮格《伊雍》而開始練習觀察無意識（記夢日記、睡前積極想像、記錄白天的意象），並說「以下是從一月十五日到十九日這五天的觀察日記的改寫」。榮格框架是文章的骨架，**保留，不要刪**。
- **緊接著一段免責說明**，用 `<strong><span class="kaiti">` 包住：

  > 【說明：本文夢境與積極想像中出現的真實人物，是作者的無意識所借用的形象；其中的言語、行為與象徵意義，均不應視為對當事人現實性格、意願或經歷的客觀描述。文中涉及往事的敘述，也出自作者個人的記憶與感受，可能存在遺漏或偏差，不代表對相關事件唯一或完整的事實版本。】

  **涉及真實人物的意識流創作，這段一定要有。**
- **用 `<h2>` 標日期分段**（`一月十五日，星期四，早晨`），不是 `custom-divider`。
- **夢境敘述 → 榮格式自我詮釋**交替推進；每段夢後面接一段「從榮格的觀點來看，這個夢是否是…」的解讀。
- 專有名詞（阿尼瑪、積極想像、伊雍）掛腳注解釋。
- 配圖用 AI 生成圖，`figcaption` 標「（ChatGPT 生成圖）」。
- 標題呼應**契訶夫《一個小公務員之死》**；手法是「以瑣碎細節對照死亡」製造反諷、長句、聯想式跳接。
- 收尾 🌏。

### 取材時的鎖定原則

素材是好幾天的完整對話紀錄，**不要全部倒進去**。鎖定一條情節線（9-10 鎖的是「龐君華會督之死」那五天），與該線無關的生活絮語剪掉；但**與該線交織的夢境、積極想像、神學頓悟要留**——那正是這個文類的內容本身。

## 五、鐵則：保真，不虛構（這是他的真實人生）

- 所有人名、日期、事件、引述**只能來自素材本身**。查不到、記不清的，寧可不寫，不要「合理推測」補細節（生卒年、頭銜、地點都易錯，見 [`interview-article`](../interview-article/SKILL.md) 9.6 的捏造事實清單）。
- **隱私與敏感揭露要先問**：素材含使用者高度私人的內容（如同志身分、家庭、醫療、身體、對在世第三人的評價）。寫進公開文章前，**逐項標示出來請使用者確認去留**（參 [`interview-article`](../interview-article/SKILL.md) 9.14）。預設保留與「主題核心」直接相關者、刪去無關隱私。
- 詩歌歌詞、經文、引文逐字照抄，不要改寫或「潤飾」。
- 涉及真實人物的意識流／夢境創作，開篇一定要放第四節那段免責說明。

## 六、流程

1. 讀本 skill ＋ [`nonchurch-house-style`](../nonchurch-house-style/SKILL.md) ＋ 撈 2-3 篇張辰瑋範本對齊聲音。
2. **確認他要的是哪一類**（自傳體／評論長文／意識流獨白）與**這一篇要收進哪一期的哪個位置**（決定 id、category、section、sort_order）。系列文先查前一集編號。
3. 取材：讀寫作計畫 + 對應日期的 `C:\tmp\krishna\*.json` / 手工稿 / 他口頭給的概念，**抽出鎖定情節線的逐字片段**。
4. **成文：Claude 寫「寫作簡報」→ Gemini 執筆 → Claude 查證與套體例**（見第三節）。小標意象化不編號；收尾 🌏。
5. **先給使用者看草稿**（尤其意識流獨白與含隱私的稿），標出需確認的揭露點，再上架——這是他的個人創作，不要直接寫進 DB 就算數。
6. 確認後，用 [`upload-article`](../upload-article/SKILL.md) pipeline 寫進 articles（`is_published=false`）＋投稿管理那筆（`linked_author_ids: [2]`，他是既有作者，不要建 `newAuthor`）。
7. 預覽 `/articles/{id}`、校稿、跑 house-style 第八節的自檢、再開 `is_published`。

## 七、不適用

- 一般訪談稿 → [`interview-article`](../interview-article/SKILL.md)
- **別的作者的稿 → [`upload-article`](../upload-article/SKILL.md)，只做編輯，不要套用張辰瑋的聲音**
- 編輯室報告／本期作者簡介等結構頁 → [`issue-frontmatter`](../issue-frontmatter/SKILL.md)
  （編輯室報告**署名編輯室但實際上就是他寫的**，是他的第四種模式：第一人稱主編位置、交代本期生成過程、兼具宣言性。
  **骨架照 `issue-frontmatter`，文氣照本篇第二節**——刊務報告那段尤其是他本人的聲音，可以寫他的升學、修課、心境、做的夢，
  但那些**不准進 summary 或 SEO description**（memory `feedback_writing_style` 第 6 點）。）
