# 保留《無境界者》作者聲線

## 核心原則

- 把作者風格當成編輯護欄，不當成憑空捏造作者經歷、觀點或引言的許可。
- 先辨識「文字角色」：親筆作者、共同作者、受訪者、訪問者、翻譯、配音。`linked_author_ids` 只表示關聯，不等於文字作者。
- 依證據等級控制改寫幅度。`穩固` 可選擇已辨識的文類；`暫定` 只保留可直接觀察的特徵；`口語限定` 只用於訪談整理；`不足` 不推定聲線。
- 同一作者有多種模式時，按新稿的素材與文類選一種主模式；除非原稿本來混合，否則不要把全部特徵揉在一起。
- 保留作者的不規則、口語、長短句、懷疑與立場；不要把所有文章修成同一種「雜誌腔」。

## 工作流程

1. 從使用者說明、檔名、稿件署名或 `articles.author` 確認作者。名稱不一致時，以 `authors.id`、`real_name`、`linked_author_ids` 與署名角色交叉確認。
2. 讀 [作者索引](references/author-index.md)，再只讀該作者的一份 `references/authors/*.md`。不要一次載入全部作者檔。
3. 判斷工作類型：
   - **校訂既有成稿**：原稿聲音優先，作者檔只用來防止過度潤飾。
   - **素材整理成文**：只使用素材中存在的事實、感受與立場，按作者既有模式組織。
   - **訪談整理**：受訪者套口語限定特徵；問題、簡介與串場仍屬編輯文字。
   - **缺少可歸因文本**：採《無境界者》一般編輯規範，保留原稿，不模仿不存在的文風。
4. 依作者檔逐層校訂：先保留觀點與敘事順序，再調整段落、句法、詞彙、標題與收尾。每層都以「是否仍像此人」為判準。
5. 事實、人名、日期、引文與個人經歷不得為了像作者而補寫。無來源處標記待確認。
6. 需要上架時，再接 [`upload-article`](../upload-article/SKILL.md)；訪談接 [`interview-article`](../interview-article/SKILL.md)。本 skill 本身不寫入資料庫。

## 特殊路由

- 張辰瑋：讀作者檔後，必須再讀 [`chenwei-essay`](../chenwei-essay/SKILL.md)；後者的保真、隱私確認與三種寫作流程優先。
- 龐君華：本 skill 只處理《無境界者》文章聲線；講道、論文與典藏流程分別使用既有 `pong-*` skills。
- HTML、腳注與圖片格式遵循專案 `AGENTS.md` 與 `stores/word_to_sql.md`，不要把排版慣例誤當作者聲線。

## 更新作者檔

有新作品時，先在專案根目錄執行：

```powershell
node .agents/skills/preserve-nonchurch-author-voice/scripts/audit-author-coverage.mjs
```

若新作呈現穩定的新結構、語氣或文類，才新增一種模式；單篇偶發差異先記入「待觀察」。更新來源清單與證據等級，不以文章數量取代文本判讀。
